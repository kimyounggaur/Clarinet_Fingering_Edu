# 클라리넷 손·손가락 SVG 운지표 업그레이드용 바이브코딩 마스터 프롬프트

## 0. 목적과 사용 방법

이 문서는 첨부된 `clarinet_standard_fingering_chart.html`, `clarinet_standard_fingering_chart.svg`, `clarinet_standard_fingering_chart.pdf`를 **운지 데이터의 단일 기준(source of truth)** 으로 삼아, 손과 손가락 SVG를 추가한 정교한 교육용 차트로 업그레이드하기 위한 실행 프롬프트다.

코딩 에이전트에게 세 원본 파일과 이 문서를 함께 제공하고, 아래의 **마스터 지시문부터 단계별로 수행**하게 한다. 중간 단계에서 운지 데이터를 임의로 다시 쓰거나, 키 번호를 추측하거나, 외부 이미지 파일을 복사해 넣지 않는다.

---

## 1. 마스터 지시문

당신은 다음 역할을 동시에 수행한다.

1. 표준 보엠식 B♭/A 소프라노 클라리넷의 운지 데이터를 다루는 음악 교육용 시각화 엔지니어
2. 데이터 기반 SVG를 설계하는 시니어 프런트엔드 개발자
3. 인쇄용 A2 벡터 포스터와 접근성 높은 반응형 웹앱을 제작하는 UI 엔지니어
4. SVG→PDF 변환과 렌더링 회귀 검사를 수행하는 품질 보증 엔지니어

### 최종 목표

첨부 원본의 다음 요소를 손실 없이 유지한다.

- 표준 보엠식 기보음 E3-A6의 반음계 42개 음
- 기본 운지 42개
- 대체 운지 19개
- `COMPONENTS`의 25개 키/구멍 좌표
- `ROUND_IDS`, `HORIZONTAL_IDS`
- 각 음의 `primary`, `alternate`, `midi`, `register`, `registerKo`
- 샬뤼모, 목음역, 클라리온, 알티시모 구분

그 위에 다음 기능을 추가한다.

- 왼손과 오른손의 원본 벡터 실루엣
- 왼손 엄지, 검지, 중지, 약지, 새끼손가락
- 오른손 검지, 중지, 약지, 새끼손가락
- 오른손 엄지받침 지지 위치
- 누르는 손가락과 열린 손가락의 시각적 차이
- 직접 접촉 손가락과 기계적으로 연동되어 닫히는 키의 구분
- 고정도법 한글 계이름과 영문 음이름의 병기
- B♭/A 클라리넷 실음 표시
- 대체 운지 표시, 음역 필터, 검색, 키보드 탐색, 누름 애니메이션
- A2 가로 인쇄/PDF 레이아웃

### 반드시 생성할 파일

```text
clarinet_solfege_hand_fingering_chart.svg
clarinet_solfege_hand_fingering_chart.pdf
clarinet_solfege_hand_fingering_chart.html
```

가능하면 다음 보조 파일도 만든다.

```text
src/fingering-data.js
src/clarinet-svg.js
src/hand-model.js
tests/validate-data.mjs
README.md
```

## 2. 절대 변경 금지 규칙

1. 원본 HTML의 `DATA`를 눈으로 보고 재입력하지 말고, 코드로 추출하여 사용한다.
2. 42개 음의 순서와 MIDI 52-93의 연속성을 바꾸지 않는다.
3. 대체 운지가 없는 음에 임의의 운지를 추가하지 않는다.
4. 원본의 `primary`와 `alternate` 배열에서 키 ID를 추가·삭제·교체하지 않는다.
5. 알티시모 운지를 “더 일반적이다”라는 이유로 다른 자료의 운지로 덮어쓰지 않는다.
6. SVG 안에 래스터 손 사진을 넣지 않는다. 모든 손, 손가락, 악기, 키는 독자 제작한 벡터여야 한다.
7. 외부 CDN, 외부 폰트, 외부 자바스크립트 라이브러리, 외부 이미지 요청을 사용하지 않는다.
8. HTML은 파일을 더블클릭해도 동작하는 완전한 단일 파일이어야 한다.
9. PDF는 이미지 한 장을 넣은 래스터 PDF가 아니라 벡터 중심 PDF여야 한다.
10. 오른손 엄지는 음을 만들기 위한 누름 손가락으로 표시하지 말고, 항상 엄지받침 지지로 구분한다.

## 3. 1단계: 원본 분석과 데이터 잠금

### 3.1 원본 파일 확인

다음 순서로 파일을 읽는다.

1. `clarinet_standard_fingering_chart.html`
2. `clarinet_standard_fingering_chart.svg`
3. `clarinet_standard_fingering_chart.pdf`

HTML에서 다음 상수를 정규식 또는 AST로 추출한다.

```js
COMPONENTS
ROUND_IDS
HORIZONTAL_IDS
DATA
REGISTER
```

### 3.2 데이터 검증 어설션

개발을 시작하기 전에 아래 어설션을 통과시킨다.

```js
assert(DATA.length === 42)
assert(DATA.filter(n => n.alternate).length === 19)
assert(DATA[0].midi === 52)
assert(DATA.at(-1).midi === 93)
assert(DATA.every((n, i) => n.midi === 52 + i))
assert(COMPONENTS.length === 25)
assert(allKeyIdsAreIntegersBetween0And24)
assert(noteIdsAreUnique)
assert(midiValuesAreUnique)
```

### 3.3 원본 시각 비교

원본 PDF 1페이지를 200dpi 이상으로 렌더링한다. 다음을 기록한다.

- A2 가로형 7열 × 6행 카드 구조
- 음역별 왼쪽 색상 띠
- 붉은색 누름 키
- 흰색 열린 키
- 기본/대체 운지 병렬 배치
- 헤더와 범례 위치

원본 시각 구조는 참고하되, 손 SVG를 넣기 위해 카드 내부 여백과 도식 비율은 개선할 수 있다.

## 4. 2단계: 계이름과 이조 데이터 모델

### 4.1 고정도법 계이름 매핑

```js
const SOLFEGE_KO = {
  C: "도", "C♯": "도♯", "D♭": "레♭",
  D: "레", "D♯": "레♯", "E♭": "미♭",
  E: "미",
  F: "파", "F♯": "파♯", "G♭": "솔♭",
  G: "솔", "G♯": "솔♯", "A♭": "라♭",
  A: "라", "A♯": "라♯", "B♭": "시♭",
  B: "시"
}
```

예시:

```text
E3      → 미3
F♯3     → 파♯3
G♭3     → 솔♭3
A♯4/B♭4 → 라♯4/시♭4
```

### 4.2 기보음과 실음

- B♭ 클라리넷 실음 MIDI = 기보 MIDI - 2
- A 클라리넷 실음 MIDI = 기보 MIDI - 3
- 운지 데이터는 항상 기보음 기준으로 유지한다.
- 악기 선택은 제목과 실음 표시만 바꾸며 `primary`/`alternate` 배열에는 영향을 주지 않는다.

### 4.3 표기 모드

HTML에서 다음 3개 모드를 제공한다.

```text
계이름 + 영문
계이름만
영문 음이름만
```

## 5. 3단계: 손가락 ID와 직접 접촉 모델

### 5.1 손가락 ID

```text
LT = 왼손 엄지
L1 = 왼손 검지
L2 = 왼손 중지
L3 = 왼손 약지
L4 = 왼손 새끼손가락
RT = 오른손 엄지, 엄지받침 지지 전용
R1 = 오른손 검지
R2 = 오른손 중지
R3 = 오른손 약지
R4 = 오른손 새끼손가락
```

### 5.2 키 ID에서 손가락으로의 접촉 규칙

다음 규칙은 원본의 25개 추상 키맵에 손가락 교육 레이어를 덧씌우기 위한 **직접 접촉 모델**이다.

| 손가락 | 관련 키 ID | 처리 규칙 |
|---|---:|---|
| LT | 1, 3 | 레지스터 키 또는 엄지 구멍 중 하나라도 활성화되면 누름 |
| L1 | 0, 4 | A 키 또는 왼손 검지 구멍 |
| L2 | 8 | 왼손 중지 구멍 |
| L3 | 13 | 왼손 약지 구멍 |
| L4 | 2, 9, 10, 11, 12, 14, 15, 16 | 상단/왼손 새끼손가락 레버 군 |
| R1 | 5, 6, 7, 17, 19 | 사이드 키, 오른손 검지 구멍, 슬리버 계열 |
| R2 | 18 | 오른손 중지 구멍 |
| R3 | 20 | 오른손 약지 구멍 |
| R4 | 21, 22, 23, 24 | 하단/오른손 새끼손가락 레버 군 |
| RT | 없음 | 항상 엄지받침을 지지하되 운지 누름으로 집계하지 않음 |

### 5.3 연동 키 예외

원본 패턴에서 `15` 또는 `16`과 `24`가 동시에 활성화되는 경우가 있다. 이때 `24`는 별도의 오른손 새끼손가락 접촉으로 집계하지 않는다.

```js
const rightPinkyPressed =
  [21, 22, 23].some(id => pattern.includes(id)) ||
  (pattern.includes(24) && !pattern.includes(15) && !pattern.includes(16))
```

이 규칙이 필요한 이유는 도식이 “닫힌 키/패드”를 표시하고, 손가락 레이어는 “직접 누르는 손가락”을 표시하기 때문이다. 두 개념을 혼동하지 않는다.

### 5.4 손가락 계산 함수

```js
function activeFingers(pattern) {
  const p = new Set(pattern)
  const out = new Set()

  if ([1, 3].some(id => p.has(id))) out.add("LT")
  if ([0, 4].some(id => p.has(id))) out.add("L1")
  if (p.has(8)) out.add("L2")
  if (p.has(13)) out.add("L3")
  if ([2, 9, 10, 11, 12, 14, 15, 16].some(id => p.has(id))) out.add("L4")
  if ([5, 6, 7, 17, 19].some(id => p.has(id))) out.add("R1")
  if (p.has(18)) out.add("R2")
  if (p.has(20)) out.add("R3")
  if ([21, 22, 23].some(id => p.has(id)) ||
      (p.has(24) && !p.has(15) && !p.has(16))) out.add("R4")

  return ["LT", "L1", "L2", "L3", "L4", "R1", "R2", "R3", "R4"]
    .filter(id => out.has(id))
}
```

## 6. 4단계: 손 SVG 설계

### 6.1 좌표계

원본 키맵은 약 `x=-12..10`, `y=-12..68` 범위를 사용한다. 새 도식은 다음 뷰박스를 사용한다.

```html
<svg viewBox="-34 -21 68 105">
```

클라리넷은 중앙 `x≈0`, 왼손은 화면 오른쪽의 상관부, 오른손은 화면 왼쪽의 하관부에 배치한다.

### 6.2 손바닥

- 왼손 손바닥: `x=13..28`, `y=-3..39`
- 오른손 손바닥: `x=-29..-12`, `y=30..71`
- 따뜻한 피부색 그라디언트를 사용한다.
- 손바닥은 악기 뒤에, 손가락과 손끝은 악기 위에 렌더링한다.
- 손바닥 불투명도는 0.75-0.85로 두어 키가 완전히 가려지지 않게 한다.

### 6.3 손가락 벡터

각 손가락은 다음 요소로 구성한다.

```text
두꺼운 cubic Bézier 외곽선
피부색 내부선
중간 관절 원
타원형 손끝
접촉점 원
활성 손가락의 붉은 반투명 halo
```

활성 손가락:

- 피부색은 유지한다.
- 외곽선과 접촉점만 붉게 강조한다.
- 손가락 전체를 진한 빨강으로 칠하지 않는다.

열린 손가락:

- 손끝이 구멍/키에서 4-7 SVG 단위 떨어져 있어야 한다.
- 접촉점은 흰색 내부 + 갈색 외곽선으로 표시한다.

### 6.4 손가락 목표점

- L1/L2/L3의 일반 구멍: 키 중심이 아니라 악기 오른쪽 가장자리 쪽으로 손끝을 이동한다.
- R1/R2/R3의 일반 구멍: 악기 왼쪽 가장자리 쪽으로 손끝을 이동한다.
- LT는 엄지 구멍 또는 레지스터 키 좌표를 따른다.
- L4/R4는 해당 패턴에서 활성화된 레버의 중심을 우선순위로 선택한다.
- 비활성 손가락은 고정된 “대기 목표점”을 사용한다.

### 6.5 오른손 엄지

- `RT`는 하관 뒤쪽의 엄지받침을 잡는 짧은 손가락 벡터로 표시한다.
- 항상 표시한다.
- 붉은 누름 상태로 만들지 않는다.
- 손가락 요약에는 “오른손 엄지(지지)” 칩으로 별도 표시한다.

### 6.6 저작권과 독창성

- 실제 손 사진을 트레이싱하지 않는다.
- 제조사의 운지표 이미지를 복제하지 않는다.
- 첨부 파일의 데이터와 추상 키맵은 유지하되, 손/악기 외형은 독자 벡터로 만든다.

## 7. 5단계: 클라리넷 SVG 개선

### 7.1 악기 본체

다음 부분을 분리한다.

```text
마우스피스
배럴
상관
하관
벨
연결 링
키 로드
25개 키/구멍 컴포넌트
```

### 7.2 재질 표현

- 본체: 짙은 흑단/그레나딜라 느낌의 좌우 선형 그라디언트
- 키워크: 은색 계열
- 열린 키/구멍: 흰색 또는 매우 밝은 회색
- 닫힌 키/구멍: `#C12B43`
- 활성 키 외곽선: `#7F1D2D`

### 7.3 SVG 재사용

정적 SVG에서는 `<defs>` 안에 `clarinet-base`를 정의하고 각 운지 도식에서 `<use>`로 재사용한다. 활성 키만 각 도식에 오버레이한다.

```html
<defs>
  <g id="clarinet-base">...</g>
</defs>

<g class="diagram">
  <g class="hand-palms">...</g>
  <use href="#clarinet-base"/>
  <g class="fingers">...</g>
  <g class="pressed-keys">...</g>
</g>
```

HTML의 동적 SVG에서는 동일한 레이어 순서를 문자열 생성 함수로 구현한다.

## 8. 6단계: 정적 SVG 포스터 사양

### 8.1 페이지

```text
물리 크기: 594mm × 420mm
방향: A2 가로
viewBox 예시: 0 0 1800 1273
카드: 7열 × 6행
```

### 8.2 헤더

헤더에 다음을 표시한다.

- `클라리넷 계이름 운지법 차트`
- `손·손가락 SVG 가이드`
- `표준 보엠식 B♭ / A 소프라노`
- `기보음 E3-A6`
- `고정도법 계이름`
- 기본 42개 + 대체 19개

### 8.3 범례

범례는 최소 4개 항목을 가진다.

```text
붉은 키/구멍 = 누름 또는 막음
흰 키/구멍 = 열림
붉은 손끝 = 직접 누르는 손가락
연한 손가락 = 열림/대기
```

### 8.4 카드

각 카드에 다음을 포함한다.

```text
주 계이름
이명동음 계이름
영문 음이름
음역 배지
기본 운지
대체 운지(있는 경우)
손·손가락이 포함된 미니 SVG
```

대체 운지가 없으면 기본 도식을 카드 중앙에 배치한다.

### 8.5 푸터

- 음역 범위
- 42개 기본 + 19개 대체
- 제조사별 키 모양 차이 안내
- 교육용 독자 벡터임을 표시

## 9. 7단계: 인터랙티브 HTML 사양

### 9.1 완전 독립 실행

- CSS, 데이터, SVG 생성 함수, JS를 한 HTML 안에 넣는다.
- 네트워크 요청이 0건이어야 한다.
- `file://`로 열어도 동작해야 한다.

### 9.8 애니메이션

`손가락 누름 재생` 버튼을 누르면:

1. 열린 상태의 손가락이 살짝 바깥에서 시작
2. 손가락별 55-70ms 지연
3. 손끝이 키/구멍으로 이동
4. 키/구멍이 붉은색으로 채워짐
5. `prefers-reduced-motion: reduce`에서는 즉시 상태 변경

## 14. 시각 품질 기준

1. 손가락은 막대기처럼 보이지 않도록 손바닥, 관절, 손끝을 가진다.
2. 손은 악기를 완전히 가리지 않는다.
3. 열린 손가락과 누른 손가락의 차이가 색뿐 아니라 거리와 접촉점으로도 드러난다.
4. 붉은 키와 붉은 손끝은 같은 의미 계열이지만 서로 구분된다.
5. 작은 카드에서도 왼손/오른손 구분이 가능하다.
6. 큰 도식에서는 손가락 라벨이 겹치지 않는다.
7. 이명동음 표기가 긴 음에서도 음역 배지와 충돌하지 않는다.
8. 대체 운지가 있는 카드에서 두 도식의 폭이 균형을 이룬다.
9. 인쇄물은 화면보다 대비를 높이고 그림자 효과를 최소화한다.
10. 흑백 인쇄에서도 활성 키를 외곽선과 접촉점으로 구분할 수 있어야 한다.

## 15. 접근성 기준

- 모든 운지 SVG에 `role="img"`와 의미 있는 `aria-label`
- 카드가 `<button>` 또는 키보드 포커스 가능한 요소
- 선택 카드에 시각적 강조와 `aria-current` 또는 동등한 상태
- 필터 버튼에 `aria-pressed`
- 포커스 패널에 `aria-live="polite"`
- 색상만으로 상태를 표현하지 않음
- 본문 대비 WCAG AA 수준
- 애니메이션 정지 또는 reduced-motion 지원
